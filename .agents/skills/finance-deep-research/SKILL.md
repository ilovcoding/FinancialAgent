# 深度研究（多空辩论流水线）

移植自 TradingAgents 多智能体框架的深研流程，适配 ZCode 原生 agent 循环。你会依次扮演流水线中的每个角色；分析师阶段可用 `finance-analyst` 子代理并行取证。**全程证据必须来自 finance MCP 工具或 WebSearch，禁止编造数字。**

## 角色与流程（按顺序执行）

### 第 0 步 · 标的身份锚（防幻觉）

用 `mcp__finance__search_securities` 解析标的，确认公司全称/代码/行业。后续所有角色的回答都必须使用这个身份，防止"看着数据编一家公司"。

### 第 1 步 · 四分析师取证

一次性并行调用工具（或派 `finance-analyst` 子代理），产出四份简报（各 ≤200 字）：

- **市场分析师**：`get_daily`——趋势、区间、量能、关键支撑/阻力位（用真实价格标注）
- **基本面分析师**：`get_financials` + `get_daily_basic`——盈利质量、成长性、估值分位
- **资金面分析师**：`get_moneyflow` + `get_ownership`——主力资金方向、股东变化
- **新闻分析师**：WebSearch 近期新闻/公告/研报 3-5 条，逐条标注来源与情绪（正面/负面/中性）

### 第 2 步 · 多空辩论循环（默认 1 轮）

严格交替发言，每一方必须引用第 1 步的证据（标注 [S1]=市场 [S2]=资金 [S3]=新闻 [S4]=基本面）：

- **Bull 第 1 轮**：给出 3 个最强的看多论据，每个锚定具体数据
- **Bear 第 1 轮**：先直接反驳 Bull 论据中最弱的一条，再给出 3 个看空论据
- （若用户要求 2 轮：Bull 第 2 轮须承认 Bear 的正确之处后再反击；Bear 第 2 轮同理）

**辩论纪律**：承认对方正确论点不算失败；不得使用"可能/也许"回避立场；每个论据必须有 [S#] 引用。

### 第 3 步 · 研究经理裁决

综合辩论给出五档评级之一：**买入 / 增持 / 持有 / 减持 / 卖出**。必须包含：

- 评级 + 一段裁决理由（谁的证据链更完整可验证）
- 证据均衡度评分（0-10）与置信度（低/中/高）
- **反偏差规则**：证据均衡时应选"持有"，不得为给方向而硬造方向；偏离中性必须有可验证的数据理由

### 第 4 步 · 交易提案与风控三方

- **交易员**（非建议，是研究推演）：入场参考区间与止损位**必须锚定**市场分析师给出的支撑/阻力位与近期波幅，给出仓位参考区间和时间跨度
- **风控三方**各一句话：激进（为何可进）、保守（最大风险与仓位上限）、中立（折中方案与验证节点）

### 第 5 步 · 组合经理终审（最终输出格式）

```
# {公司名}（{ts_code}）深度研究报告

## 摘要
评级 | 目标区间 | 时间跨度 | 置信度（一行表格）

## I. 分析师简报（四段）
## II. 多空辩论与裁决（含双方论据与经理裁决全文）
## III. 交易提案（推演性质，锚定数据）
## IV. 风控三方复核
## V. 终审结论
核心逻辑 / 催化剂 / 风险提示 各 1-3 条

---
*本报告由多智能体系统自动生成，数据截至 {最新交易日}，仅供研究参考，不构成投资建议；判断与决策由投资人做出。*
```

## 边界与纪律

- 报告是研究推演不是投资建议，免责声明必须保留。
- 任何工具失败（积分不足/限流）时如实标注"该数据源暂缺"，不得用旧数据冒充或编造。
- 若用户对同一标的已有历史深研，先读取之前的报告，在终审说明与上次评级的异同。
